josesaid / outbox-demo

Transactional Outbox + Idempotent Consumer

A dependency-free Java demo of two patterns that keep event-driven systems consistent: save the business change and its event in one transaction, and make the consumer skip duplicates.

Run it

cd outbox-demo
javac -d out $(find src -name "*.java")
java -cp out com.mx.development.jose.said.Main

Scenarios

ScenarioExpected result
A. Normal flow1 payment
B. Relay crashes after publishDuplicate published, consumer skips it
C. Consumer crashes before offset commitMessage redelivered and skipped
D. Temporary broker failureFAILED → FAILED → SENT
E. Permanent broker failureFAILED → FAILED → DEAD, no payment

Key ideas

  • Same transaction: OrderService.createOrder writes the order and the outbox row together; nothing goes to Kafka inside it.
  • At-least-once delivery: OutboxRelay may publish an event twice, so the consumer must be idempotent.
  • Idempotency in the transaction: PaymentConsumer.handle inserts into processed_events first; a duplicate rolls back the business write.
  • Key = aggregate ID: events of one order stay in one partition and keep their order.
  • Offset commit last: committed only after the database commit.
